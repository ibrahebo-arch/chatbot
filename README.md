# VI Iraq 🇮🇶 — استوديو طلب فيديوهات بالذكاء الاصطناعي

واجهة عربية (سطح مكتب وموبايل): دردشة مع مساعد إبداعي (ChatGPT) يطوّر فكرة الزبون ويقترح أفكاراً وسيناريو ويرى الصور المرفقة، ولوحة طلب تحدد الجودة والمدة واللغة وعدد الشخصيات مع السعر الفوري. قبل أول رسالة تعرض الدردشة مقاطع متحركة قصيرة (طبيعة، صحراء، بحر، ألعاب، ونماذج من أعمالنا).

## كيف يعمل الطلب

1. الزبون يكتب فكرته ويرفع صوراً أو فيديو (صور: jpg/png/webp/gif/heic حتى 20 MB، فيديو: mp4/mov/webm حتى `ATTACH_LIMIT`). لكل ملف دور: **شخصية 1 / 2 / 3** أو **مرجع**. الملفات تُرفع إلى Cloudflare R2 (دلو خاص).
2. ما يكتبه الزبون في الدردشة (مثل "30 ثانية" أو "720p" أو "باللهجة العراقية") يضبط لوحة الطلب والسعر مباشرة.
3. **معرّف تيليغرام ورقم هاتف عراقي إلزاميان** ويُتحقق منهما في الخادم وقاعدة البيانات؛ بدونهما لا يُنشأ أي طلب ولا يُرسل شيء.
4. عند الإرسال يُنشأ الطلب في Postgres (`request_id` مثل `VI-261012-K3F9`)، طلب واحد كل 20 دقيقة لنفس الزبون/الهاتف/المعرّف (`ORDER_COOLDOWN_MINUTES`)، ويستطيع الطلب من جديد فور استلام الفيديو، ولا يتكرر عند إعادة المحاولة (Idempotency-Key).
5. ChatGPT يكتب **ملف الإنتاج** ويُحفظ في `orders.brief_md`، ويصل للمشرفين على تيليغرام كملف `.txt`.
6. **مع الدفع (`WAYL_API_KEY`)**: الطلب يبقى **مسجّل** (`queued`) وتظهر نافذة وزر **ادفع** بالمبلغ بالدينار. بعد أن يؤكد Wayl الدفع ينتقل إلى **مراجعة** (`awaiting_admin`) – انظر قسم «الدفع عبر Wayl». **بدون الدفع**: يبقى `queued` حتى يضغط الزبون Start في البوت. في الحالتين ينتظر `awaiting_admin` حتى يرسل المشرف `/confirm` (عندما `AUTO_GENERATE=false`) فيصبح **قيد الإنجاز**، ثم **جاهز** عند التسليم.
7. المشرف يسلّم الفيديو بـ `/deliver`: يُحفظ في R2 (`videos/<request_id>.mp4`)، يصل للزبون على تيليغرام، ويظهر في صفحة الدردشة (الحالة تتحدث كل 5 ثوانٍ).

## التشغيل محلياً

```bash
npm install
cp .env.example .env     # ثم عدّل القيم
# DATABASE_URL: Postgres محلي، مثل postgresql://postgres:postgres@localhost:5432/vi_iraq
# R2_* يمكن تركها فارغة محلياً: الملفات تُحفظ مؤقتاً في مجلد temp للتجربة فقط
# TELEGRAM_POLL=1 لتجربة البوت محلياً (لا تفعّله مع نسخة منشورة بنفس التوكن)
npm start                # http://localhost:3000
npm test                 # اختبارات التحقق؛ اختبارات القاعدة تحتاج TEST_DATABASE_URL
npm run check            # فحص الصياغة لكل الملفات
```

### قاعدة البيانات والـ migrations

- الاتصال من `DATABASE_URL` فقط (لا يُكتب في أي ملف ولا يُطبع). SSL يُستخدم فقط مع الرابط الخارجي لـ Render (`*.render.com`)؛ الرابط الداخلي على Render لا يحتاجه.
- عند التشغيل يُنفّذ الخادم ملفات `migrations/*.sql` بالترتيب، كل ملف مرة واحدة (تُسجّل في جدول `schema_migrations`)، ثم يبدأ الاستماع. إذا فشلت يتوقف برسالة واضحة.
- الجداول: `requesters`، `orders`، `assets`، `events` (سجل كل تغيير حالة)، `telegram_admins`.
- `TEST_DATABASE_URL` يشغّل اختبارات القاعدة داخل schema مؤقت يُحذف بعد الانتهاء.

## متغيرات البيئة

| المتغير | الوصف |
|---|---|
| `DATABASE_URL` | Postgres. على Render يُحقن تلقائياً من `vi-iraq-db` |
| `OPENAI_API_KEY` / `OPENAI_MODEL` | مساعد الدردشة وكتابة ملف الإنتاج (الافتراضي `gpt-4o-mini`) |
| `R2_ACCOUNT_ID` / `R2_ACCESS_KEY_ID` / `R2_SECRET_ACCESS_KEY` / `R2_BUCKET` | Cloudflare R2 للمرفقات والفيديوهات (دلو خاص، روابط مؤقتة ساعة واحدة) |
| `DEMO_DELIVERY` | **مرحلة التجربة المجانية** (`true`): الحالات تتقدم كل ثانية (مسجّل › مراجعة › قيد الإنجاز › جاهز) ويستلم الزبون فيديو عشوائي من `public/loops` في الدردشة، وعلى تيليغرام إذا ضغط Start. اجعلها `false` عند تفعيل الدفع |
| `BREVO_API_KEY` أو `RESEND_API_KEY` | البريد: بريد 1 عند وصول طلب جديد (مع ملف الإنتاج)، بريد 2 عند تسليم الفيديو (مع الفيديو) |
| `MAIL_FROM` / `MAIL_TO` / `MAIL_ATTACH_MB` | المرسل، بريد الاستلام (`ibrahim2dms@gmail.com`)، أقصى حجم للمرفقات |
| `AUTO_GENERATE` | `false` (الافتراضي): كل طلب ينتظر `/confirm` من المشرف |
| `TELEGRAM_BOT_TOKEN` | توكن بوت التسليم من BotFather (@MyAIVideoDeliveryBot) |
| `TELEGRAM_ADMIN_CHAT_IDS` | معرّفات محادثات المشرفين (اختياري؛ أو أرسل `/admin ADMIN_TOKEN` للبوت) |
| `TELEGRAM_POLL` | `1` للتطوير المحلي فقط؛ النسخة المنشورة تستخدم Webhook تلقائياً |
| `ADMIN_TOKEN` | كلمة مرور المشرف (`/admin` في البوت و `x-admin-token` في `/api/requests`) |
| `PUBLIC_URL` | رابط الموقع العام (لـ Webhook تيليغرام) |
| `ATTACH_LIMIT` | أقصى حجم لفيديو مرفق (الافتراضي `200mb`) |
| `ANTHROPIC_API_KEY` / `CLAUDE_MODEL` / `HIGGSFIELD_API_KEY` | للتوليد التلقائي (الخطوة القادمة – غير مستخدمة بعد) |

### ⚠️ المساعد لا يرد؟ (OpenAI)

1. يجب أن يوجد ملف `.env` فعلي (ليس `.env.example` فقط) وفيه `OPENAI_API_KEY`.
2. أعد تشغيل الخادم بعد أي تعديل على `.env` (`npm start`).
3. إذا كان هناك متغير `OPENAI_API_KEY` قديم في إعدادات Windows (متغيرات البيئة) فالخادم يتجاهله ويأخذ القيمة من `.env`.
4. عند التشغيل يطبع الخادم `AI: on` أو سبب التعطيل، وأي خطأ من OpenAI يظهر في الطرفية كـ `chat error:`.

## الدفع عبر Wayl

| الحالة للزبون | الحالة في القاعدة | متى |
|---|---|---|
| مسجّل | `queued` | بعد إرسال الطلب – نافذة «مسجّل طلب VI-…» وزر **ادفع** |
| مراجعة | `awaiting_admin` | بعد أن يؤكد Wayl الدفع (يصل المشرفين «💰 تم الدفع» على تيليغرام) |
| قيد الإنجاز | `prompt_ready` / `generating` | بعد `/confirm` |
| جاهز | `completed` / `delivered` | عند التسليم |

- **`WAYL_API_KEY`** يُنشئ رابط الدفع (`POST /api/v1/links`) عند ضغط «ادفع»؛ الرابط يُعاد استخدامه حتى ينتهي (`WAYL_LINK_EXPIRES`)، ورقمه المرجعي `VI-…-P1` (ثم `P2` إذا انتهى أو أُلغي).
- **`WAYL_VERIFY_KEY`** يقرأ الرابط من Wayl (`GET /api/v1/links/:ref`) للتأكد من الدفع. لا يُعتمد أبداً على ما يرسله المتصفح أو الـ webhook: الطلب يُعلَّم مدفوعاً فقط عندما يعيد Wayl نفسه `Complete`/`Delivered` بنفس المبلغ، ومرة واحدة فقط.
- التحقق يحدث: عند وصول الـ webhook (`/api/wayl/webhook`)، أثناء انتظار الزبون في الصفحة (كل ثانيتين)، وكل دقيقة في الخلفية لأي رابط غير مدفوع (احتياطاً إذا لم يصل الـ webhook).
- بعد الدفع يعود الزبون إلى `/paid` فتظهر حالة طلبه مباشرة.
- المبلغ = السعر بالدولار × `PAY_IQD_PER_USD` مقرّباً لأعلى إلى 250 د.ع (الحد الأدنى 1000).
- `WAYL_ENV=test` روابط اختبار، `live` دفع حقيقي. `PAY_PUBLIC_URL` = النطاق المسجّل في متجر Wayl (الافتراضي `PUBLIC_URL`).

## التجربة المجانية (fal.ai)

في تبويب **الاستوديو** يظهر مفتاح **«طلب فيديو كامل / 🎁 جرّب مجاناً»** عند ضبط `FAL_KEY`. في وضع التجربة **لا يظهر أي سعر** ولا خانات التواصل: الزائر يكتب فكرته في الدردشة، يختار **واقعي / كرتون** و**صورة / فيديو**، ويضغط «أنشئ مجاناً». **ChatGPT (`PROMPT_MODEL`، الافتراضي `gpt-6-sol`) يكتب الوصف من المحادثة**، والنتيجة تظهر في الدردشة مع زر **تنزيل** (صورة أو فيديو) وزر **«حرّكها فيديو»**.

- **صور الكرتون** بموديل ChatGPT (`chatgpt-image-latest`، ~$0.04 للصورة) وتُحفظ على السيرفر؛ **الصور الواقعية** عبر fal (FLUX، ~$0.003).
- **إذا نفد رصيد fal** تتحول كل الصور إلى ChatGPT تلقائياً لمدة 10 دقائق ثم يُعاد تجريب fal. الفيديو يحتاج fal (واجهة فيديو Sora من OpenAI أُغلقت في 24/9/2026)، فيتوقف الفيديو المجاني حتى يُشحن الرصيد.

| الإعداد | الافتراضي | المعنى |
|---|---|---|
| `TRIAL_IMAGES` / `TRIAL_VIDEOS` | 3 / 1 | لكل IP خلال `TRIAL_WINDOW_DAYS` (30) يوماً |
| `TRIAL_VIDEO_SECONDS` | 5 | طول الفيديو |
| `TRIAL_DAILY_BUDGET_USD` | 5 | سقف الصرف اليومي، بعده تتوقف التجربة حتى الغد (حماية من تغيير الـ IP/VPN) |
| `FAL_IMAGE_MODEL` | `fal-ai/flux/schnell` | ~$0.003 للصورة |
| `FAL_VIDEO_MODEL` / `FAL_I2V_MODEL` | `minimax/h3-max-turbo/…` | ~$0.025 للثانية (~$0.125 للفيديو) |

- **كل نتيجة مجانية لها تذكرة** `FT-YYMMDD-XXXX` (تظهر للزائر على البطاقة)، ونسخة من الصورة/الفيديو تُحفظ على السيرفر (`trial/<التذكرة>`). المشرفون يصلهم على تيليغرام «🎁 تذكرة مجانية» مع الملف؛ وفي البوت: `/free` (آخر 10) و`/free FT-…` (التذكرة مع ملفها). عبر الـ API (`x-admin-token`): `GET /api/trials` و`GET /api/trials/:ticket/file`.
- الـ IP لا يُحفظ أبداً، فقط بصمة مشفّرة (HMAC). الطلب الذي يفشل لا يُحتسب على الزائر.
- فلتر الأمان في fal يبقى مفعّلاً، والشروط تُعرض على الزائر كما في الدردشة.
- كل مزود/موديل خلف `media.js` (`submit` / `poll`) – يمكن إضافة Hugging Face أو غيره بدون تغيير بقية الموقع.

## بوت تيليغرام للتسليم

- بعد إرسال الطلب يظهر للزبون زر **افتح بوت التسليم** (`t.me/MyAIVideoDeliveryBot?start=رقم-الطلب`). الضغط على Start يربط محادثته بالطلب؛ بدون هذه الخطوة لا يستطيع البوت مراسلته (قيد من تيليغرام).
- المشرف يسجّل نفسه مرة واحدة بإرسال `/admin ADMIN_TOKEN` للبوت (يُحفظ في قاعدة البيانات)، فتصله كل الطلبات الجديدة مع ملف الإنتاج.
- الربط بـ Start يقبل فقط حساب تيليغرام نفسه المكتوب في الطلب.
- أوامر المشرف: `/pending` · `/confirm ID` (يبلّغ الزبون أن العمل بدأ) · `/deliver ID` كتعليق على فيديو أو `/deliver ID رابط` (يرسل الفيديو للزبون) · `/status ID`.
- للأتمتة (بـ `x-admin-token`): `GET /api/requests`، `POST /api/requests/ID/confirm`، `POST /api/requests/ID/deliver` مع `{ "url": "..." }` أو `{ "file": "اسم-ملف-في-uploads" }`.
- حد تيليغرام للبوتات: 50 MB للملف المرفوع و20 MB للفيديو عبر رابط.

## مقاطع العرض (public/loops)

مقاطع 8 ثوانٍ صامتة H.264 تُعرض في الدردشة قبل أول رسالة. المصادر والتراخيص في `public/loops/CREDITS.md`. لإضافة مقطع: ضع `name.mp4` وصورة `name.jpg` في المجلد.

## فيديوهات المعرض (للقراءة فقط)

لا يستطيع زوار الموقع رفع أو حذف فيديوهات المعرض؛ يمكنهم فقط إرفاق فيديو داخل الدردشة مع الطلب.

**من المجلد:** انسخ ملفاتك `.mp4` / `.webm` إلى `public/videos/` وأعد تحميل الصفحة.

اسم البطاقة = اسم الملف.

## ماذا يحدث عند "إرسال الطلب"؟

- يُحفظ الطلب في Postgres (جدول `orders`) مع المحادثة وملف الإنتاج، والمرفقات في R2 تحت `uploads/<request_id>/`. لا شيء يُحفظ على قرص الخادم (Render المجاني يمسح القرص عند كل نشر).
- يصل المشرفين على تيليغرام: ملخص الطلب + ملف الإنتاج كملف `.txt`، ويصل بريد إلى `MAIL_TO` عند كل طلب جديد وبريد ثانٍ عند تسليم الفيديو.
- الزبون يرى حالة طلبه في الدردشة (مسجّل → مراجعة → قيد الإنتاج → جاهز) ويشاهد الفيديو عند جاهزيته.

> **مرحلة التجربة الحالية** (`DEMO_DELIVERY=true`): كل الطلبات مجانية، الحالات تتقدم تلقائياً كل ثانية، ويستلم الزبون فيديو عشوائي من مقاطع العرض. عند تفعيل الدفع: `DEMO_DELIVERY=false` فيعود مسار موافقة المشرف (`/confirm` ثم `/deliver`). التوليد التلقائي (Higgsfield) هو الخطوة القادمة.
